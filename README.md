# HeadRouter — Task-Aware Dynamic Attention-Head Pruning

HeadRouter decides **per request** which attention heads an LLM needs. A tiny classifier predicts
the task of the incoming prompt, a registry supplies the head mask that was profiled offline for
that task, and the model runs with those heads **physically removed** — the Q/K/V/O weight
matrices are sliced, so the pruned heads are never computed and the KV cache is smaller.
Static pruning removes the same heads for every input; HeadRouter changes the mask from request
to request.

```
prompt ─► [1] task classifier (MiniLM + logistic regression, ~2 ms)
              │  low confidence / "general" ─► dense model
              ▼
          [2] head-mask registry (artifacts/head_masks.json)
              ▼
          [3] pruned execution engine (pre-sliced weights per task, pointer swap)
              ▼
          [4] telemetry: latency, TTFT, ms/token, tokens/s, GPU energy (NVML), memory, accuracy
```

## Method

1. **Offline profiling.** For each task, 128 calibration examples are run with a gate `g = 1` on
   every head's output; importance is `E_x |∂L(x)/∂g|` with the loss on the gold answer tokens
   only (Michel, Levy & Neubig, NeurIPS 2019), L2-normalised per layer. The mean output of every
   head is recorded as well.
2. **Mask construction.** Heads are pruned lowest-importance first at sparsity 10–50 % with
   constraints: ≥ 2 heads kept per layer, heads that rank in the top 10 % for *every* task are
   protected, and an optional GQA-group mode removes whole KV groups (shrinks K/V and the KV cache).
   For each task the highest sparsity whose dev score stays within the accuracy budget
   (1.5 % relative) is selected. Scores are re-computed after every step with the mask active
   (iterative pruning) and are not layer-normalised.
3. **Bias compensation.** A removed head's expected contribution `W_o[:, h] · mean_h` is folded
   into the O-projection bias (as in FLAP, An et al., AAAI 2024). This costs nothing at inference
   and avoids the large accuracy collapse that zero-ablation causes on a compact model.
4. **Online inference.** The classifier routes the prompt; if confidence < 0.8, or the prompt is
   not one of the profiled tasks, the dense model is used. Otherwise the task's pre-sliced weights
   are activated (a dictionary lookup, no slicing on the hot path).

Dense and pruned runs go through the same attention code, so timing differences come only from the
removed work. The dense path is bit-identical to stock Hugging Face attention (see tests).

## Run

```bash
./run_pipeline.sh            # full pipeline (classifier, profiling, masks, benchmark)
./run_pipeline.sh --quick    # small sample sizes, fast smoke run
.venv/bin/python run_demo.py # dashboard at http://localhost:8000
.venv/bin/python -m pytest -q tests
```

The dashboard's **Live Compare** tab runs your prompt twice — dense and HeadRouter — and shows
both outputs with measured end-to-end latency, prefill time, ms/token, tokens/s, GPU energy and
output agreement. The other tabs show per-task importance heatmaps with the selected masks, the
accuracy-vs-sparsity sweep and the benchmark results.

## Results (Qwen2.5-1.5B-Instruct, bf16, RTX A2000 12 GB)

Full numbers, plots and the Markdown report are regenerated by `scripts/04_benchmark.py` into
`artifacts/results/`. From the run used during development:

| Task (test split) | Heads pruned | Dense | Static (1 global mask) | Random (same sparsity) | HeadRouter |
|---|---|---|---|---|---|
| Sentiment (SST-2, acc) | 40 % | 0.928 | 0.932 | 0.554 | 0.926 |
| QA (BoolQ, acc) | 30 % | 0.778 | 0.774 | 0.444 | 0.762 |
| NLI (MNLI, acc) | 0 % (dense) | 0.778 | 0.756 | – | 0.778 |
| Math (GSM8K, EM) | 0 % (dense) | 0.445 | **0.015** | – | 0.445 |
| Summarization (CNN/DM, ROUGE-L) | 0 % (dense) | 0.199 | 0.174 | – | 0.197 |

- A single static mask (10 %) destroys GSM8K; HeadRouter prunes heavily only where the task tolerates it.
- Random masks at the same sparsity collapse accuracy, so the gradient importance scores matter.
- Classifier: 96.7 % accuracy on held-out prompts with varied phrasings, ~2–3 ms per prompt.
- Speed with the 40 % sentiment mask: 3.9 % end-to-end on short prompts; at 4 096 input tokens
  prefill is 11 % faster and decoding 17 % faster per token (`context_sweep.png`).

Design studies (`scripts/ablation_study.py`, `scripts/iterative_study.py`, plots via
`scripts/plot_studies.py`) showed that zero-ablation collapses accuracy at 20–30 % sparsity, that
mean bias compensation fixes much of it, and that raw (not layer-normalised) iterative gradient
scores keep accuracy best.

Caveat: masks are validated on each task's metric (label prediction, exact match, ROUGE). Long
free-form explanations under a pruned mask can drift more than the label does.

## Realistic expectations

Attention projections are a small share of a modern GQA model's weights (≈12 % per layer in
Qwen2.5-1.5B; the MLPs and the 151k-token LM head dominate). Batch-1 decoding is memory-bandwidth
bound, so pruning a third of the heads gives single-digit-percent decode speedups. Savings grow
with input length, because the attention kernel's cost grows quadratically with context while the
MLP cost does not; the context-length sweep in the benchmark measures this.
